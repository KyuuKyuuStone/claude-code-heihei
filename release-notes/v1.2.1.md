# Claude Code Heihei v1.2.1

协作可观测性与自愈的一轮修复：让**卡住的会话真的能被自动救回**，让**静默失败不再静默**（配额耗尽、诊断日志归因、派活是否真被消费），并清理一批死代码。

## 协作自愈

- **假死自动重推真正生效**：修复旧状态机的一处确定性缺陷（首次超时判定即抛异常并被静默捕获，该机制此前从未成功触发过）——现在「运行中但长时间无活动」的员工会话会被自动重推；无进程的会话只告警、不自动拉起。

## 可观测性：静默失败显性化

- **配额/限流错误可见化**：provider 返回 429（尤其"使用上限已用完"一类）时，向会话注入**明确提示并附限额重置时间**——此前这类错误只落在轨迹日志里，用户看到的是"会话突然不说话了、没有任何报错"（2026-09-16 实战：后端会话因此静默 18 分钟）。
- **诊断日志按会话归因**：诊断记录补上 `sessionId`，排查时可直接按会话定位，不必再靠时间戳猜。
- **服务端启动自证**：服务端启动时留下可核对的启动记录，便于确认"当前跑的到底是哪一份"。
- **派活消费回执**：新增消费回执通道——可查询一条派活**是否已被真正消费**。**投递成功 ≠ 已被消费**，此前这两者无法区分（2026-09-14 实战：文件写入信箱后长时间未被处理，却没有任何可查的状态）。
- **诊断 fallback 保留策略**：明确诊断主文件不可用时的降级保留策略，避免关键现场被静默丢弃。

## 清理

- **pet 死代码清理**：移除桌面端已不调用的宠物相关服务端代码及配套测试，**净删 600+ 行**（桌面端功能早已下线，仅余死代码）。

## 界面

- **角色多语言与中文路径提示**：角色相关文案补齐多语言；涉及中文路径的场景给出更清晰的提示。

## 升级说明

- 无破坏性变更。从 v1.2.0 直接检查更新即可升级。
- 已保存的协作方案、花名册、会话数据完全兼容。
- 配额/限流提示为新增行为，不改变既有的重试与限流逻辑。
