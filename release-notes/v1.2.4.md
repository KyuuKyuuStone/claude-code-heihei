# Claude Code Heihei v1.2.4

员工生命周期（增删 / 重新加入）闭环：让**移除这件事真的生效、可追溯、可复盘**，并把误操作变成可行动提示。

## 员工生命周期

- **移除留痕**：两条移除路径（正常移除 / 运行中残留清理）都会写入 `servant_removed` 诊断事件，**含身份快照**——谁被移除了、当时是什么角色/工作目录，事后可查。
- **「删除」真正生效（修复）**：此前 DELETE 后未失效身份缓存，**被删员工重启后仍会按旧身份被注入**。现已补齐缓存失效，删除即为删除。
- **派活到已移除会话：从 500 改为可行动 404**：以前向已移除会话派活会撞成 500（看不出所以然）；现在返回明确的 404，并**放行主管的汇报路径与禁用员工的合法场景**，让人知道下一步该做什么，而不是对着服务器错误猜。
- **重复登记提醒**：同一 workDir 下、同一 role 重复登记时写入 `servant_duplicate_role` 日志提醒——**只提醒、不阻断**（可能是有意为之，例如同时段并行两人）。
- **重新加入 = 全新登记**：重新加入按全新登记处理，配合上面的留痕，**诊断链可完整复盘**（移除 → 重新登记）。

## 界面

- **协作设置新增「删除 vs 禁用」说明**（简中/繁中/英/日/韩）：明确两者语义差别，避免把「临时停用」当成「永久删除」。

## 工程质量

- **.gitignore 忽略协作运行时文件**：忽略 `.heihei/`（协作信箱与运行时状态）与派活协议临时载荷 `.dispatch-payload.json`，不再反复触发「清单外未跟踪文件」。

## 升级说明

- 无破坏性变更。从 v1.2.3 直接检查更新即可升级。
- 已保存的协作方案、花名册、会话数据完全兼容。
- 「派活到已移除会话」的响应码由 500 变为 404：若有下游按 500 判定，请改按 404 处理（语义更准确，且属修复而非新行为）。
