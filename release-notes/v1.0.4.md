# Claude Code Heihei v1.0.4

本版本重做本地模型的**上下文规划**与**跑分运行方式判定**：高配机器不再被 32K 上下文封顶，全 GPU 运行不再被误标成"混合"。

## 上下文按硬件规划上限

- **不再封顶 32K**：此前规划器把 32K 当作目标值，硬件再好也只给 32K。现在改为预算内逐级上探——32K 保底（Claude Code 真实负载所需），预算充裕时自动规划 64K / 96K / 128K。
- **档位取舍**：64K 档优先 f16 KV（无质量损失）；96K / 128K 档自动改用 q8_0 KV（省一半显存/内存，质量损失极小）换取更大上下文。
- 举例：RTX 5070 Ti（16GB 显存）跑 7.5B 模型，现在会规划 **128K q8_0**；16GB 内存的纯 CPU 机器也能规划 96K。装不下 32K 的低配机器行为不变（q8_0 → 4K 步进降档，下限 8K）。

## 跑分运行方式判定修复

- **全 GPU 不再误标为「GPU + CPU 混合」**：跑分 100% 档在能读出模型层数时，GPU 层数参数是具体数字（如 28 层模型的 28）而非 -1，旧判定只认 -1，导致明明全部层都在显卡上（如 RTX 5070 Ti 实测 108 t/s），横幅却写「混合运行」。现在 ngl 覆盖全部 GGUF 层数即判定为 GPU 全量。
- 「应用推荐配置」生成的方案名称与横幅随之显示正确的运行方式。

## 升级说明

- 无破坏性变更。已保存的本地模型方案兼容；想吃到新上下文规划，重新跑一次跑分并点「应用推荐配置」即可。
