# Claude Code Heihei v1.2.3

通知降噪与协议修正：按**用户定的产品规则**重划「什么该进对话流」，并同步协议真源、补齐信箱回执。

## 系统通知规则变更（产品规则）

- **对话流只保留需要人响应的消息**（如员工汇报）。
- **系统事件一律降为诊断日志**：员工登记、假死告警、崩溃上报、报错升级、熔断通知等不再投进会话窗口打扰人。
- 这些事件仍**完整可查**，维护入口：`~/.claude/cc-heihei/diagnostics/`。

## 无进程提醒

- 改为**仅在「存在未被消费的派活」这一可行动场景**才记录——即"确实有事没人接"时才提示。
- 文案**中性化，禁用惊悚词**。
- **正常闲置零打扰**：会话空转不再产生提醒。

## 协议与信箱

- **协议真源同步**：原先"熔断后会通知主管"的承诺改为**诊断自查指引**（与上一条降噪规则一致）。
- **文件信箱投递补记消费回执**：经信箱投递的派活同样登记消费回执，可判定"这条活有没有被接住"，不再对假死告警判定隐形。

## 诊断

- **闲置诊断去重**：同一 episode 只记一条，避免重复记录淹没日志。

## 升级说明

- 无破坏性变更。从 v1.2.2 直接检查更新即可升级。
- 本次仅改变**系统事件的通知去向**（会话流 → 诊断日志），不影响员工汇报等需人响应消息的送达。
