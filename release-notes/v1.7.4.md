# Claude Code Heihei v1.7.4

**结构债收官版**：v1.7.0 结构专项立下的三项验收目标本版**全部收口**——五个巨型文件的行数目标（G1）、分层违规清零（G2）、服务端（root）类型关卡（G9）。同时修掉一批**用户实际会撞到的桌面缺陷**（面板/弹窗静默失败、协作设置弹窗永久转圈、未登记会话无法登记、超时被当成失败），并新增**「上下文接近上限 → 一键压缩」**入口。**无破坏性变更**。

## 桌面缺陷修复（用户可见）

### 面板/弹窗「静默失败」普查全批修（A1–A6）

此前多处「有 loading 面、有 error 变量，但**错误从不显示**」：删除失败、拉取失败、提交失败、目录浏览失败、原生目录对话框失败都只落 console，界面照旧、用户以为没点。

现在统一改为**失败态 + 重试**（错误文案走统一的人话映射），六处全修：删除提供商失败、提供商列表拉取失败、任务提交失败、最近项目加载失败、目录浏览失败、原生对话框失败。

**一处设计洞（测试抓到）**：原生对话框流程开始前菜单会先关闭，失败态**无处可显示**——把失败态**上移到外层持有**，并在原生流程失败后**重开菜单**，面板重新挂载后失败提示仍在。

### 协作设置弹窗对「不在花名册的会话」永久转圈（v1.7.3 #2）

根因：原判断无法区分「花名册**还没加载完**」与「**确实没这条**」——后者恒为真，于是永久停在加载态、提交按钮一并锁死。现在拆成**加载中 / 就绪 / 不在花名册（可重试）/ 拉取失败**四态：不在花名册给出**明确失败提示 + 重试**，拉取失败给出**可重试的失败态**，二者不再混为一类。

### 未登记会话现在可以登记为协作会话

上一版把「未登记」与「查询失败」混成同一类并给了一条**伪重试死路**（本版修正）。现在：**未登记（永久）放行表单**——填写并保存即通过既有 upsert 路径完成**首次登记**；**仅拉取中/拉取失败**才锁提交。文案改为引导语（「该会话尚未登记为协作会话；填写以下信息并保存即完成登记。」）。

### 「请求超时」不再呈现为业务失败

`Request timed out after 320s` 此前被当普通错误**弹红条**，暗示「失败/重试」；实际它只断了连接、**业务仍在后台跑**。现在超时文案改为**「连接已超时；任务可能仍在后台运行，稍后刷新即可查看结果」**，turn-change 错误条在超时态改用**中性提示条**（五语言同步）；默认请求超时同步由 **120s 提升到 320s**。

### 新建协作会话菜单新增「（选择目录…）」

此前想给**新项目**开协作会话只能绕道（先建普通会话、再改目录）。现在「新建会话」菜单直接给一条**选择目录**入口，复用既有原生目录选择。

### 协作任务台账按钮图标

台账按钮的 `ListChecks` 与活动流按钮图标**同像素冲突**，按设计师定稿在**同族内换字**为 `ClipboardList`（label/行为/状态一律未动）。

## 上下文：接近上限提示与一键压缩（R1）

- **接近上限即提示**：上下文用量接近窗口时给出提示条 + **一键压缩**按钮；阈值**直接取 CLI 返回值**（`autoCompactThreshold`，已按 provider 覆盖后的窗口推导）——不自行推算，天然与 CLI 实际行为**同口径**。
- **按钮是普通发送**：复用既有 send 通道发 `/compact`（CLI 本地命令），**零新协议、零 CLI 改动、零服务端改动**；已核实该路径**不会被 `skipSlashCommands` 吃掉**。回合进行中按钮禁用，防重复触发。
- **压缩结果有反馈**：区分「正在压缩 / 已压缩 / 压缩后仍超窗」；区分依据是压缩后**重新取数**，不是猜测。
- **两个入口、一份实现**：`/context` 面板与**上下文指示器的悬停弹层**共用**同一个组件与同一批文案键**（不新造第二套）。弹层本体是 `pointer-events-none`（不可见时浮在输入区上方），故入口**只在弹层可见时可点**，避免隐形按钮吞掉点击。
- **面板取数补一次短重试**：压缩刚结束时 CLI 常仍在收尾，那次 `get_context_usage` 失败会直接落成错误；现在 post-compact 取数失败会**延迟 5s 自动重试一次**，仍失败才显示错误。
- **口径统一三处**：用量饱和时**显式显示「≥窗口」**（不再用钳到 100% 的数字误导）、分类明细行与总量**同尺**、面板 Context 页与弹层一样打**「估算」**标（该数据同走 `estimateOnly` 通道）。
