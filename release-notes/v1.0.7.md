# Claude Code Heihei v1.0.7

本版本针对 09-10 实战反馈的两个顽固问题做**根治**（而非仅改模板/文档）：员工汇报乱码在服务端彻底兜底、主诊断日志"静默停写"变为可感知可恢复；并修正主管编排行为与协作会话身份丢失。

## 员工汇报乱码：服务端自动修复（一劳永逸）

- **根因补全**：v1.0.5 已把派活模板的员工汇报命令改为「Write 写文件 + `--data-binary`」，但**存量会话的旧上下文、以及手动安装在 `~/.claude/skills/work-orchestrator/` 的旧版磁盘技能**仍在指示员工用内联 `curl -d`——Windows 终端按 GBK 编码发出，服务端按 UTF-8 解析，乱码依旧。
- **服务端编码嗅探**：`/api/session-messages`（及协作身份接口）现在以严格 UTF-8 解码请求体，失败时自动回退 GBK 解码——**旧模板、老会话、存量习惯发来的中文汇报全部自动修复**，无需任何会话或技能变更。
- 旧模板仍建议更新（新写法更稳），但乱码不再依赖它。

## 排查指引：删除旧版磁盘技能

- 若你曾按早期文档手动安装过 `~/.claude/skills/work-orchestrator/SKILL.md`（2026-08 的旧版本），请**删除或改名**它——内置技能已随应用自动更新，旧磁盘副本会持续把过时的派活/汇报命令注入主管会话。本次已实测：正是这份 8/21 的磁盘副本导致升级后乱码依旧。

## 主诊断日志"静默停写"可感知、可恢复

- **根因**：主诊断文件（diagnostics.jsonl，20MB 上限）被外部进程锁住时（编辑器打开、索引器占用等），所有追加写入持续失败，且失败被静默吞掉——表现为日志"停写一天"无人知晓（09-09 实测：diagnostics.jsonl 与 runtime-errors.log 恰好停在 20MB/5MB 上限）。
- **修复**：主文件写入失败时自动**降级写旁路文件**（`diagnostics-fallback-<日期>.jsonl` / `runtime-errors-fallback-<日期>.log`，事件带 `degraded:true` 标记），并在服务端 stdout（electron-host.log）留痕告警——停写从此可发现、事件不丢失。

## 主管编排行为与协作会话身份

- **主管默认派活，不自己干**：履新消息与协作协议明确「收到任务的第一反应是拆解并派活」——只有用户点名要主管亲自做、或没有合适员工时才自己动手。修复首次任务时主管倾向自己干、需要用户催促才派活的问题。
- **协作会话身份不再因改目录而丢失**：修复空协作会话在切换工作目录时被"替换"导致员工连身份一起从花名册消失的问题——替换时协作身份与模型配置会自动过继到新会话。
