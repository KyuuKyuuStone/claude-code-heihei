# Claude Code Heihei v1.6.0

**让协作拥有原生任务闭环**：从派活、员工汇报到主管验收与返工，任务状态统一记录在项目隔离的台账中；主管与员工会话可按角色使用原生协作工具，服务不可用时支持文件信箱降级。

## 任务台账与协作闭环

- **任务状态统一以台账为准**：派活创建 `dispatched` 任务；员工开始处理后进入 `accepted` / `in_progress`；汇报推进到 `delivered`；主管验收通过进入 `verified`，要求返工则进入 `rework`，员工再次处理后可重新汇报。非法状态流转会被拒绝。
- **广播逐目标记账**：每个员工各自获得独立任务和 `taskId`，共享 `broadcastId` 用于关联。带相同 `broadcastId` 的并发请求会在单个服务端进程内串行处理，跳过已成功投递的目标并复用已有任务结果；不带 ID 的请求不加锁，不同 ID 互不阻塞。
- **汇报目标可靠解析**：派活消息末尾带有系统生成的汇报页脚；员工汇报按任务台账确定派活人。旧主管交接后，旧任务可改投同项目现任主管。若显式 `taskId` 在台账中查不到，服务端记录诊断告警，并按既有回退规则处理。
- **任务按项目隔离并持久化**：台账按项目保存，服务启动时可从记录恢复任务状态与历史；任务状态变化会通知客户端刷新。

## CLI 原生协作工具

- 新增 `CollabDispatch`、`CollabReview`、`CollabListTasks`、`CollabReport`：主管可派活、验收和查看台账；员工可汇报并查看派给自己的任务。主管返工时填写意见，工具会向原员工发送同一 `taskId` 的返工消息。
- 工具按协作角色注入：主管获得派活、验收、列表工具；员工获得汇报、列表工具（不能派活）；普通会话不注入协作工具。
- 工具只依据任务台账报告状态，不暴露或推断会话回合状态字段。

## 协议与离线降级

- 主管协作协议改为原生工具优先，并保留受限的安全手动兜底。仅在工具未注入，或传输故障且文件信箱不可写时使用；业务错误不得通过手动请求绕过。工具返回 `queued` 表示已写入信箱，不代表送达，不应重复补发。
- **文件信箱降级**：服务不可用时，派活和汇报可写入项目工作目录下的 `.heihei/dispatch/`，服务恢复后由服务端消费。派活复用客户端生成的 `taskId`，重试不会重复创建台账任务；汇报信箱 payload 可附任务报告信息，由服务端先更新台账再投递消息。
- **受限旧服务端兼容**：新旧服务端混装不属于支持场景。连接到不具备任务台账能力的旧服务端时，Dispatch / Report 可能降级投递消息但无法记录台账；Report 仅在同项目花名册能确定唯一主管时回退投递，否则安全拒绝。Review / List 无法降级到旧接口，会如实报告不支持。

## 稳定性与已知限制

- **本机信任边界**：协作服务仅限本机（`127.0.0.1`），默认不做进程级鉴权；本机以同一用户权限运行的程序可以读写协作数据。`taskId` 是任务标识符，不是访问凭证。此边界已知并接受；代码依据：`src/server/index.ts:92-103,226-231,277-285`、`src/server/localRequestPolicy.ts:281-307`。目前 `callerSessionId` 在 report / review API 可省略；v1.7 计划改为必填，如未来支持远程访问再引入本机 API 令牌，依据：`src/server/api/collabTasks.ts:133-135` 与 `D:/xxw_p/cc-heihei-plan/架构决策_taskId信任边界.md:35-42`。

- **汇报误投防护（v1.6.0 后续小版本补入）**：任务 ID 属于其他员工时，HTTP 汇报不按该 ID 改投，并回退解析发送方名下唯一派活人；没有未结任务时尝试同项目主管，多派活人来源时保留原目标。信箱不推进他人任务，但仍投递汇报消息；缺失/空白 `fromSessionId` 时信箱不推进台账。请使用派活页脚中的 `taskId`。实现/测试：`src/server/services/reportTargetResolver.ts:115-170,208-227`、`src/server/__tests__/report-target-resolver.test.ts:103-146,224-270`、`src/server/services/dispatchMailboxService.ts:382-424`、`src/server/__tests__/dispatch-mailbox.test.ts:238-350`。未知 taskId 另记 `collab_report_task_not_found`，不触发“他人任务”回退。

- 对已验收通过（`verified`）的任务再次提交 `pass`，返回成功并附 `already_final` 告警，不会重复记录；对已结单任务（`verified` / `failed` / `cancelled`）提交其他验收结果（例如对已通过的任务要求返工），返回 `409` 冲突。如需返工已通过的任务，请重新派活。
- **终态不能退回返工**：已 `pass` 的任务不能再改为 `rework`，会返回 `409`。
- 员工必须先接受任务或进入执行状态，任务才可汇报；尚处于 `dispatched` 时汇报会被拒绝，工具会按既有行为短暂重试或如实报告台账未更新。
- 新旧服务端混装（新 CLI 连接旧版无台账服务端）不属于支持场景：Dispatch / Report 可能降级投递但无台账，Review / List 会报台账不支持。
- 任务面板与上下文自动续接不在本版，计划于 **v1.6.1** 跟进。

## 升级说明

- 本版新增按项目隔离的任务台账文件；任务状态以服务端台账为准。
- 建议桌面应用与 CLI 使用同一版本，以获得完整的台账、验收与列表能力。
