# Claude Code Heihei v1.7.1

**错误更好懂、Windows 保存不再失败**：修掉一个 Windows 上「保存项目/本地 agent 编辑必然失败」的真缺陷；错误提示改为「人话标题 + 可折叠技术详情」，并把 26 处瞬时提示从英文技术串改成人话；协作消息的手写汇报也能被折叠；另有内部结构收尾与首次跑通全量自动化测试。**无破坏性变更**。

## 修复：Windows 上「保存 agent 编辑」必失败

- **现象**：在 Windows 上更新（保存）一个项目/本地 agent 的编辑**必然失败**——不是偶发，是每次。
- **根因**：写入时用的是一个「数值形式」的文件打开标志。原意是防止误写符号链接，但在 Windows 上其中一个安全标志位实际是 `undefined`（相当于没生效），使这串数值变成了 **513**——这个组合带着「清空原文件」却**没带「文件不存在就创建」**，被系统直接判为非法参数而拒绝。所以问题不在「某个标志不被支持」，而在**标志组合本身在 Windows 上非法**。
- **修法**：Windows 上改用**字符串形式的打开方式**（语义与原意一致：覆盖写入、必要时创建）；**非 Windows 分支与原来逐字相同**，原有的安全检查一处未动。
- **值得说明的是**：这个缺陷是**跑测试**发现的——测试基线里它一度被判为「平台不支持、跳过即可」，复核后确认为产品真缺陷，跳过只会把用户故障藏进绿色的基线。修复后该文件 **12 项全过（原 9 过 3 败，3 条自然转绿）**。

## 错误提示更清楚

- **错误态新增「人话标题 + 可折叠技术详情」**：以前出错只有一个原始错误串；现在默认展示人话说明，右侧有「技术详情 ▾」按钮，**默认折叠**，展开可看到原始错误、错误分类与时间，并可一键复制。信息层级以人话为主，技术块用中性灰、不抢错误红的视觉。
- **26 处瞬时提示人话化**：散落各处的英文技术错误串（如超时、连接失败）改为中文人话；**业务错误仍原样显示**（有信息量的不翻译）。
- **跨项目操作的 409 提示接入人话**：此前这类拒绝会直出英文，现在显示可读说明（本条对应「跨项目派活被拒绝」）。
- **根崩溃屏不再只显示一行原始串**：应用启动期崩溃时，改为「双语静态标题 + 可换行、可复制的原始错误块」（该界面在界面框架加载前触发，无法使用常规的错误组件，故采用最小可行做法）。
- **五种界面语言同步**。

## 协作消息

- **手写汇报也能被折叠**：此前只有通过协作工具发起的汇报会被折叠成卡片；若手写（直接发 HTTP）则不会。现在**派活消息的页脚里加入了「手写汇报必须附任务号」的指引**——照做即可被折叠。（已派出的旧派活不追溯；新派活生效。）
- **汇报消息带上「汇报自：<角色>」**：汇报页脚新增来源角色信息，便于在折叠卡上分辨是谁汇报的。
  - **未验证/说明**：该信息的**服务端注入已就位**，但**折叠卡上把它显示出来的前端部分尚未实现**（本版只做了服务端这一半）；「员工汇报 → 折叠卡显示汇报自谁」的端到端也未实跑。

## 已知限制与未验证项

- **非 Windows 分支无法在本机运行验证**：修 Windows 缺陷时，非 Windows 的那条分支只做了静态核对，未在本机执行（本机是 Windows）。
- **图标字形与剪贴板权限需真机确认**：错误详情的展开按钮用了图标字体，「一键复制」依赖剪贴板权限——两者的真机呈现与权限行为**需在真机上确认**（未验证）。
- **协作折叠端到端未实跑**：见上文「协作消息」——「汇报自谁」的**前端展示尚未实现**，端到端未验证（本版 smoke 中对应的页脚端到端两项亦未通过，见下）。
- **出包前验证（preflight）首跑的挂账与未验证项**（如实记录，均不写成已解决）：
  - **挂账 1 项**：`src/server/__tests__/tasks.test.ts` 在流水线内红了 2 次，但**失败签名缺失**（当时 `src` 段未落盘），**独立复现 ≥4 次全绿**（含整目录负载 98 文件 / 2048 用例）；**未定栏、未登记进 known-flaky**（判定标准：签名缺失不足以证明是偶发）；**下轮 preflight 若再现即定案**。
  - **smoke 两项未通过（页脚端到端 + 反例）——非本版引入**：投递给**主管**会话的汇报，HTTP 201 成功、命令行进程已拉起（有 PID）、`turn_started` 已注入，**但该回合始终不完成、transcript 不落盘**，导致断言取不到末行；**用 v1.7.0 的包跑同一流程行为完全一致 → 不是 v1.7.1 的回归**；同一场景下员工侧会话投递正常。**已另行排查**（链路卡点、主管与员工侧差异、是否「新建且无 transcript 的主管会话」特有、以及在真实使用中投递给主管的消息会不会因此静默丢失、既有超时与可见性防护）。smoke 断言保持原样，链路问题解决后会自动转绿。
  - 因此，**smoke 的页脚端到端两项本版未能验证**（其余 4 项——工作目录状态回归、派活台账取到 taskId、产物门禁字面量 8/8、拉起超时伴生串与数值——均通过）。
- 折叠卡真机渲染、窄屏下较长的页脚行展示等，均为**未验证**。
