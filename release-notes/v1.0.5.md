# Claude Code Heihei v1.0.5

本版本聚焦**会话协作的实战可靠性**，修复一轮真实"nginx 配置同步"协作任务中主管与员工双方复盘出的高频问题。

## 汇报乱码修复

- **员工汇报命令不再内联中文**：派活消息模板里的汇报命令原先用 curl 内联中文 JSON——Windows 控制台按 GBK 编码发出、服务端按 UTF-8 解码，中文汇报必然乱码。现统一改为「Write 写 JSON 文件 → `--data-binary @file` 提交」，与主管侧一致；Bash 不可用时走文件信箱。

## 环境变量不再与 Bash 强绑定

- **上岗/履新消息注入「随身档案」**：会话 ID、桌面服务地址、文件信箱路径直接写在消息文本里——Bash 或环境变量缺失期间，员工凭消息本身就能完成汇报与自救，不再出现"知道怎么做却使不上力"的死锁。

## 工具卡死自救内置

- **ToolSearch 空结果附带自救提示**：返回 "No matching deferred tools found" 时，现在会提示可用 `select:工具名` 精确加载（如 `select:Bash,Read,Write,Glob,Grep,Skill`）。此前关键词索引失效时，这条唯一有效的恢复路径全靠模型自己猜。
- **上岗/履新消息同步写明**该自救语法，以及「computer-use 在无人值守会话不可用，勿尝试」——避免模型在无解路径上浪费多轮。

## 派活"假活"可感知

- **花名册新增 `lastActivityAt`**：员工会话最后一次活动时间随花名册 API 返回，主管可以区分"执行中"与"卡死"。
- **work-orchestrator 新增「假活检查」步骤**：派活 3~5 分钟后主动复查花名册；发现员工无活动时，发**带排障线索的催促**（附 select: 加载语法与文件信箱汇报指引），而不是只施压。

## 升级说明

- 无破坏性变更。协作会话建议升级后重新任命主管（或新开协作会话），以获取带随身档案的新版上岗消息。
