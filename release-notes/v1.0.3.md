# Claude Code Heihei v1.0.3

本版本聚焦**会话协作（主管/员工）的可靠性**：修复一起外部用户环境事故暴露的薄弱点——会话内 Bash 失效时整个派活链路瘫痪、日志把设计内回收误报成启动失败；同时重做了**新建协作会话弹窗**，支持为每个员工手动指定大模型与思考强度。

## 协作会话弹窗改版

- **手动选择大模型与思考强度**：新建/编辑协作会话时可分别为该会话指定服务商、大模型与思考强度（未改动时沿用当前全局默认）。所选配置写入会话元数据，员工被主管派活自动拉起时即以此配置运行。
- **三段式布局**：弹窗重排为「角色 / 身份 / 运行配置」三个区块——身份开关（服务其他会话、任命为主管）并排上移，核心决策一眼可见，无需滚动；预置角色下拉改为选中回显；角色特性换用标准输入组件并补充填写引导；创建后的标签页标题直接使用角色名。
- **预置角色扩充**：在原 8 个角色基础上新增 虚幻引擎开发、代码审查、翻译、技术文档、调研分析、运维脚本 6 个预置，角色描述融入行为风格措辞。

## 会话协作韧性

### 派活不再单点依赖 Bash

- **文件信箱降级通道**：会话 Bash 不可用时（典型：Windows 缺 Git Bash，所有命令返回占位符），主管/员工可改用 Write/Read 工具把派活与汇报 JSON 写到项目目录 `.heihei/dispatch/`，桌面服务端自动监听投递（等价原 HTTP 接口，保留同项目隔离校验）。投递成功自动删除文件；失败会生成同名 `.error.txt` 说明原因。
- **履新消息不再空头承诺**：任命主管时服务端会实测会话 CLI 是否内置 `work-orchestrator` 技能——确认存在才引用技能；确认不了（旧版本/外部 CLI）直接把完整派活协议内联进履新消息，保证主管始终有章可循。
- **派活协议内置故障自检**：技能与协议文本新增「故障自检」步骤（识别 shell 失效、验证环境变量、找回真实服务端口、兜底告知用户），并把文件信箱通道写进标准流程。

### 环境体检

- **设置 → 诊断新增两项协作体检**：本机 shell（Windows 检测 Git Bash，缺失时给出 `CLAUDE_CODE_GIT_BASH_PATH` 修复指引）与当前 CLI 是否内置协作技能。创建协作会话前先体检，不再让问题在派活时才暴露。

### 日志更诚实

- **预热会话回收不再误报**：预热会话在首次使用前被空闲回收（SIGTERM/退出码 143）属于设计内行为，此前会被记为「启动失败」写入 runtime-errors 日志，误导排障。现在按信息级记录，并附「正常回收、非崩溃」说明。

## 升级说明

- 无破坏性变更；员工花名册、会话数据完全兼容。使用会话协作的用户建议升级后先运行一次「设置 → 诊断 → 环境体检」。
