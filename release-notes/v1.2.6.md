# Claude Code Heihei v1.2.6

给「会话冻结」这类老毛病收尾：三条根因链路全部堵上——卡住的会话能被看见、能被救回；同时把上下文体积纳入**在线治理**（长会话不再因历史过长而无法接任务），诊断日志瘦身到可用体积，并扩大 CI 门禁。

## 冻结根因收尾（三条链路全部收口）

历次「会话冻结」是多链路叠加的结果（详见批次 2 根因调查）。本版完成最后两条：

- **工具生命周期埋点**：新增 `tool_exec_started` / `tool_result_emitted` / `tool_exec_finished` 三类诊断事件，覆盖「工具执行 → 结果回传」这段**此前完全没有埋点**的路径——工具结果到底有没有回传，现在可查证。
- **工具超时兜底**：工具执行超过**硬上限 600 秒**时，强制注入一条 `is_error` 的工具结果（提示 `timed out … may still be running; result discarded`）。此前超长命令会留下**孤儿工具调用**、会话永久悬挂；现在最坏也会拿到明确结果、正常走完这一轮。
- **注入式回合补齐 turn**：此前经文件信箱 / HTTP 注入的消息可能不建立回合状态，导致「中断」接口报 *no running turn (already idle)* 而无计可施。现在注入的回合会被正确登记——**中断对注入回合同样生效**；发送失败时对称清理，不留悬挂状态。

> 三条链路全景：① 配额耗尽静默化（v1.2.1 修复）② 工具结果丢失（本版）③ turn 状态不同步（本版）。

## 上下文体积抑制与治理

实测体积构成：固定开销约 **67 KB**（system ≈ 27 + 工具 schema ≈ 40）**不随对话增长**；`messages` 才是唯一的无界增长项（长会话中约占 **95%**）。本版按「先观测、低成本项先行」的次序落地：

**日志侧（S1 + S3）**

- **trace preview 上限 240K → 32K**：日志侧体积约 **−87%**（A5a 实测 trace 体积 99.6% 来自 preview）。**只影响落盘的日志，不影响发给模型的请求体、不影响功能**；历史文件不会缩小。
- **pending 记录改记真实体积** ＋ **preview 头尾双段采样**：修掉「1.2 MB 的请求在 pending 里只记 4.3 KB」的观测盲区；双段采样让请求尾部的 SSE usage 不再被头部截断吃掉。

**上下文治理（批次 7 核心批）——正常会话零行为变化**

- **M1 超长单条截断 + 可回查**：单条消息超过 **48 KB** 时截断，且**逐单元原文落盘**、截断处给出可读取路径——信息不丢，只是不再整条塞进上下文（多块独立落盘、失败逐条如实标注）。
- **M2 请求体积分位诊断 + 双阀告警**：每次请求记录字节数，滚动统计 **p50/p90/p99**，达到 **60% / 80%** 双阈值时告警（同一 episode 去重，不重复打扰）。
- **L1 历史裁剪（原子轮次）**：历史超预算时按**完整轮次**裁剪（**恒保留首轮 + 末 2 组**，绝不裁散工具调用与结果的配对）——**会话不再因历史过长而无法接任务**。
- **L2 动态窗口预算**：按当前模型的实际上下文窗口自适应设定预算（运行时探测另立批次，本版按静态目录值）。

> 整条消息 ≤48 KB 原样返回、历史在预算内原样返回、M2 纯观测不阻断——**正常会话零行为变化**。

## 遗留清理（两条既有测试失败根因闭合）

- **trace-capture 测试失败**＝**宿主环境变量污染**（协作宿主注入 `CC_HEIHEI_TRACE_API_CALLS=1`），并非此前猜测的顺序依赖；**workspace-service 测试失败**＝`registeredRoots` **模块级状态跨文件残留**。两者根因修复后，B2 报告的两条既有失败**全部闭合**。
- **pet 偏好端点清理 + schema 4→5 迁移**：旧键剥离不回潮 + 旧夹具回归 + 404 锁定；`check:persistence-upgrade` 脚本补注册（指向既有迁移回归测试，6/6）。

## 工程质量

- **CI 桌面测试门禁扩容 18 → 37 文件**：新增 19 个稳定文件进入 windows runner 门禁，全部满足「连续 ≥3 次本地全绿 + 确定性」标准（1104 个用例逐字一致）。
- **CI 新增 `server-tests-linux-exp` 实验 job**：ubuntu、**非阻断**（continue-on-error），一次性采集服务端测试的 Linux 兼容性清单、**用完即撤**——与 windows 门禁并列、不替换。
- **P3 清理**：local-index-corpus 套件的超时与计时语义修正（7 个假红 → **14/14 全绿**）；`client.test.ts` 环境确定性化（不再受本机凭据影响）；H5 键名兼容注释。
- 全量桌面套件：**3565 通过 / 0 失败**；全量服务端：**1628 通过 / 0 失败**。

## 升级说明

- 无破坏性变更；**正常会话零行为变化**（截断/裁剪只在超阈值时介入，且原文可回查）。
- 工具超时兜底会让「长时间无输出的工具调用」在 600 秒后拿到一个明确的超时结果（而不是继续挂起）——这是预期行为。
- trace 日志体积显著变小；排查时若需完整请求体，请依赖 `bytes` + `sha256` 与头尾采样片段。
- 长会话不再因历史过长而无法接任务：历史超预算时按完整轮次自动裁剪（首轮与最近两轮恒保留）。
