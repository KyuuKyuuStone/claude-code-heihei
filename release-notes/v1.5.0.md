# Claude Code Heihei v1.5.0

**修复花名册被误清空的高危问题**（协作身份会凭空丢失），并收口平台与架构：只做 Windows、只保留 Electron 壳、移除外部 IM 适配器、打包链统一到 bun。

## 修复

- **花名册在特定情况下会被误清空，导致协作身份丢失（高危）**：花名册的读取接口里夹带了一段"自动清理"逻辑——它把"暂时查不到会话摘要"误判成"会话已被删除"，于是**一个普通的读取请求就会把整册员工身份写盘抹掉**。摘要查不到的原因很多（索引未就绪、磁盘 IO 抖动、配置目录解析不一致），都会触发；实际表现是**员工登记后约 1 秒就被清空**，协作功能整体瘫痪（v1.4.1 及更早版本均受影响）。
  本次修复：**读取操作绝不删数据**——摘要取不到时条目照常返回（标题退化为会话 ID 前缀，不做删除）；"会话不存在"与"暂时读不到"不再被混为一谈；清理只认**明确的删除事件**。另加兜底防线：一次移除若涉及 ≥2 条、或要把整册清空，**整批跳过**并记诊断——宁可留下可手动清理的脏条目，也不让协作身份静默消失。
  顺带统一了花名册与会话两侧的配置目录解析（此前两者可能指向不同目录，是本问题的直接成因之一）。
- **图标资产门禁与平台清理的测试断链修正**：随平台瘦身清理的若干测试断言（Tauri 权限、macOS/Linux 图标集、macOS 构建脚本）已同步移除/改写，测试基线恢复全绿。

## 架构与平台

- **只做 Windows**：移除 macOS / Linux 的平台支持面（打包配置、图标集、平台专属脚本与构建链），项目定位回到"Windows 专属工作台"。
- **移除 Tauri 遗留宿主**：`src-tauri` 下的 Rust 宿主与 Tauri 配置面整体删除（该宿主早已不参与构建管线）。保留 llama.cpp 本地推理二进制、图标资源与预览 agent —— 本地模型功能照常可用。
- **移除外部 IM 适配器**：微信 / 钉钉 / 飞书 / Telegram / WhatsApp 的适配层整体移除，聚焦站内协作。
- **打包链统一到 bun**：桌面构建不再依赖 Node 侧工具链，构建更快、依赖更少（`build:preview-agent → tsc → vite build → electron-builder` 一条链）。
- **CI 扩容**：桌面测试纳入 CI 定时全量跑，覆盖面扩大。

## 升级说明

- **建议尽快升级**：花名册误清空是数据丢失级问题，且由前端轮询触发、用户侧无法规避，升级是唯一的根治办法。
- 无破坏性数据变更；从 v1.4.1 起可经检查更新直接升级（`latest.yml` + blockmap 支持增量下载）。
- 升级后如发现花名册为空，可在协作设置里重新登记员工身份；历史身份快照在诊断日志 `~/.claude/cc-heihei/diagnostics/diagnostics.jsonl` 的 `servant_removed` 事件中可查。
- 非 Windows 平台不再提供安装包；外部 IM 通道不再可用。
