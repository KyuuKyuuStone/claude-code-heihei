# Claude Code Heihei v1.5.1

**让协作更好用**：协作设置全新弹窗、角色特性文案全面升级（新增架构师），主管按花名册路由派活——便宜模型也能当好主管。另含任务台账服务端第一批与多项稳定性修复。

## 协作设置全新弹窗

- 协作设置界面重新设计：花名册管理与角色编辑集中一处，查看与调整员工的职责、约束、运行方式更直观。

## 角色特性文案 v2（新增架构师）

- 员工角色新增统一的职责说明结构：**负责什么（何时派给 TA）/ 不负责什么（边界）/ 交付物标准（必须附证据）/ 汇报要求（结论在前、证据在后、风险单列）**，共三十五个模板角色，覆盖软件开发、写作、内容运营、数据分析、学术研究与通用场景。
- 新增**架构师**角色：只在方案设计、跨模块冲突裁决、发布把关、架构守护四个节点介入，日常执行不找架构师。
- 主管派活时可按角色特性对号入座：技术方案交架构师、界面交设计师、代码质量交代码审查、验证交测试、文档交技术文档、脚本交运维脚本，不再因"省事"跳过专业验收。

## 主管按花名册派活

- 主管协议加强：主管在花名册中**按角色路由任务**——有明确对应角色时必须派给对应员工，辅助角色（架构师/审查/测试/文档）优先参与，只在花名册没有对应角色时才由主管补位并说明理由。
- 协议内置**任务类型到角色的路由表**，派活提示按花名册动态生成（rosterTable），显著降低主管会话的 token 消耗——便宜模型也能稳定履行主管职责。

## 任务台账（服务端第一批）

- 新增 `/api/collab-tasks` 任务台账接口：任务、状态与交接关系可登记可查询，为后续原生任务面板打地基。

## 稳定性修复

- **花名册写入加队列**：多名员工同时登记/更新身份时不再互相覆盖（此前并发写会互相冲掉，lost update）。
- **constraint 清除修复**：协作设置里清除员工约束档位现在能真正生效。
- **测试不再写端口文件**：跑测试不会再污染 `~/.claude/cc-heihei/desktop-server.json`；端口文件陈旧时 60 秒内自愈重建，app 重启换端口后协作汇报通道恢复更快。
- 主管会话的工作目录保护改读 `CC_HEIHEI_WORK_DIR`，与实际工作目录严格一致。

## 升级说明

- 无破坏性数据变更；经检查更新即可升级（`latest.yml` + blockmap 支持增量下载）。
- 本版为 **v1.6.0 前的过渡版本**：原生任务面板与主管原生工具在下一个大版本。
