# 本地模型

Claude Code Heihei 可以直接在你自己的电脑上运行 GGUF 大模型——不需要联网、不需要 API Key，模型和对话全留在本机。它内置了 [llama.cpp](https://github.com/ggml-org/llama.cpp) 内核，装好就能用。

适合的场景：学生写作业、做笔记、跑一些不需要巨大模型的小任务，或者你只想完全离线、不想为 API 付费。

## 打开本地模型页

点侧边栏最底部的「设置」，选「本地模型」分栏。你会看到三块：

- **硬件信息** — CPU 核数、内存、显卡（能识别的话会显示显存大小）。程序会据此推荐一个配置档位。
- **配置方案** — 一套方案 = 一个 GGUF 模型文件 + 配置档位 + 细节参数。可以建很多套，点「应用」启用。
- **运行状态** — 引擎当前是否在跑、用了哪个端口、最近的日志。

## 第一步：拿到一个 GGUF 模型

点页面上方的「下载模型」打开下载中心，里面有 Hugging Face、ModelScope（魔搭）、Ollama、LM Studio 几个 GGUF 下载网站的跳转和介绍。挑一个下载模型的 GGUF 量化版（文件名通常是 `*Q4_K_M.gguf` 这类）。

模型文件不用放特定位置，放到你方便的地方，记住路径就行。

## 第二步：建一套配置方案

1. 点「新建方案」。
2. **方案名称** — 起一个能认出来的名字，比如「写代码用 7B」。
3. **模型文件** — 点「选择模型」，选中刚下载的 `.gguf` 文件。
4. **配置档位** — 按你的硬件挑一档：
   - **低配** — 资源占用最低，纯 CPU 为主。
   - **中配** — GPU + CPU 混合，均衡取向。
   - **高配** — GPU 为主，速度优先。
   - **超级** — 大显存取向，适合更大模型。
   - **帝王** — 极限配置，榨干硬件。
5. 想要更细就展开「细节参数」，调上下文窗口、CPU 线程、GPU 层数、批处理、KV cache 类型、Flash Attention、采样参数等。
6. 点「保存」。

## 第三步：跑分，让程序替你选

不熟悉配置参数的话，可以点「跑分」，让程序实测：

1. 选一个模型文件。
2. 设**目标生成速度**（token/秒）——你希望它多快。
3. 设**上下文长度**——模型能记住多长的对话。
4. 设**硬件使用率**——GPU / CPU 占用比例，留点余量给系统。
5. 点「开始跑分」。

程序会在一档档往上调资源，直到达到你的目标速度，然后给出**推荐配置**。报告里还会告诉你这个上下文大小下 KV 缓存大概占多少显存、装不装得下。

点「应用推荐配置」就能把这份结果存成一套方案。

## 第四步：启动

回到配置方案，选好要用的那套，点「启动」。程序会内置的 llama.cpp 引擎跑起来（首次加载要等几十秒），状态变成「运行中」，旁边显示端口号。

然后到对话输入框左下角的模型选择器里换成本地模型，就能离线说话了。

:::tip
优先用「跑分」而不是自己硬配参数。跑分是按你这台机器的真实硬件测出来的，比自己猜准得多。
:::

## 常见问题

**模型加载很慢或卡住。** 看「运行状态」里的引擎日志。首次加载大模型要几十秒很正常；如果提示显存不足，把上下文调小、降低配置档位，或换更小的量化版本（比如 `Q4_K_M` 换成 `Q4_K_S`）。

**速度很慢。** 小模型、纯 CPU 跑起来本来就不快。想要快，用更大的显卡、更小的模型、或者更高的配置档位。跑分能帮你找到当前硬件下最快的组合。

**上下文装不下。** 大上下文需要更多 KV 缓存显存。跑分会告诉你大概要多少；装不下就选更小的上下文，或换 Q4 量化版本。

**它不会动手，只会一直说话。** 这是模型本身工具调用能力弱，不是配置问题。换一个更大、更强的模型试试。

模型接好了，也可以继续看 [连接模型服务](../start/models.md) 里的云端模型接法。
