# 本地模型

Claude Code Heihei 可以直接在你自己的电脑上运行 GGUF 大模型——不需要联网、不需要 API Key，模型和对话全留在本机。它内置了 [llama.cpp](https://github.com/ggml-org/llama.cpp) 内核，装好就能用。

适合的场景：学生写作业、做笔记、跑一些不需要巨大模型的小任务，或者你只想完全离线、不想为 API 付费。

## 打开本地模型页

点侧边栏最底部的「设置」，选「本地模型」分栏。你会看到三块：

- **硬件信息** — CPU 核数、内存、显卡（能识别的话会显示显存大小），以及跑分后按内存规划的上下文推荐值。
- **配置方案** — 一套方案 = 一个 GGUF 模型文件 + 参数。参数起点按你的硬件自动填好，可以建很多套，点「应用」启用。
- **运行状态** — 引擎当前是否在跑、实际 GPU 分层（如 `GPU 分层 33/37`）或纯 CPU、用的端口、最近的日志。

## 第一步：拿到一个 GGUF 模型

点页面上方的「下载模型」打开下载中心：

- **精选模型** — 内置了一份精选清单（Qwen3-4B、Qwen2.5-Coder-7B、Qwen3-8B、gemma-3-4b 视觉版等），每款标注能力档（适合聊天 / 能扛工具调用 / 能看图）、体积和 Hugging Face / ModelScope 双直链，认准 `Q4_K_M` 量化下载即可。
- **下载网站** — Hugging Face、ModelScope（魔搭）、Ollama、LM Studio 的跳转与介绍。
- **NVIDIA 加速（可选）** — 有 N 卡且跑分显示 GPU 可用时，可以从 llama.cpp 官方 Releases 下载 CUDA 版引擎（体积 1GB+，不随应用打包），在方案「细节参数 → 引擎目录」里填解压路径即可使用。

模型文件不用放特定位置，放到你方便的地方，记住路径就行。

## 第二步：建一套配置方案

1. 点「新建方案」。
2. **方案名称** — 起一个能认出来的名字，比如「写代码用 7B」。
3. **模型文件** — 点「选择模型」，选中刚下载的 `.gguf` 文件。选中后马上会显示这个模型的**能力档预告**（按参数规模估算：适合聊天 · 轻任务 / 能扛工具调用 / 能看图），多模态模型会提示需要 mmproj 投影文件才能看图。
4. **参数起点自动填好** — 线程数按 CPU 核数的 67%（实测甜点比例）、GPU 层数自动（无独显直接纯 CPU）、32K 上下文。一般不用动。
5. 想要更细就展开「细节参数」：上下文窗口、线程、GPU 层数、KV cache 类型、**视觉投影文件**（看图必需）、**长对话 KV 复用**（默认开）、**草稿模型**（投机解码提速）、**MoE 专家权重 CPU 层数**、**引擎目录**（CUDA 自定义引擎）、采样参数。
6. 点「保存」。

## 第三步：跑分，实测这台机器

点「跑分」，选一个模型文件，点「开始跑分」——不需要你填任何目标参数，程序自动实测：

- **GPU 可用性真探测**：先实跑一次 GPU 推理，跑得动才用 GPU（GTX 750 这类老卡会被正确判定并退回纯 CPU，不会启动后崩溃）。
- **67% 与 100% 两档实测**，每档测 2 次取平均降噪，推荐最快的一档。
- 报告里你会看到：
  - **运行方式结论** — 纯 CPU / GPU 全量 / GPU + CPU 混合，一眼看懂这台机器怎么跑这个模型。
  - **能力档** — 这个模型适合聊天还是能扛工具调用。
  - **首字延迟预估** — Claude Code 每次请求带约 30K 提示词，按实测输入速度折算第一句话要等多久。
  - **KV 缓存账单** — 32K 上下文的缓存要多少 GB、放显存还是内存、装不装得下。

点「应用推荐配置」会把实测最优参数（含按内存规划的上下文和 KV 缓存类型）存成一套方案，方案名直接带运行方式和实测速度，例如 `Qwen3-4B · 纯 CPU · 32K · 11t/s`。

:::tip
优先用「跑分」而不是自己硬配参数。跑分是按你这台机器的真实硬件测出来的，比自己猜准得多。
:::

## 第四步：启动

选好方案点「启动」。程序会自动处理三件事：

- **GPU 探测失败自动退纯 CPU**，引擎日志里写明原因。
- **显存/内存装不下自动降档**：GPU 配置失败退纯 CPU 重试，再不行上下文自动砍半，不会甩一堆报错给你。
- 状态变成「运行中」后，显示实际 **GPU 分层**（如 `GPU 分层 33/37`）或 **纯 CPU** 和端口。

然后到对话输入框左下角的模型选择器里换成本地模型，就能离线说话了。

## 多模态（看图）

带视觉的模型（gemma-3-4b-it、Qwen-VL 等）需要**两个文件**：主模型 GGUF + **mmproj 视觉投影文件**（同一个下载页里名字带 `mmproj` 的小文件）。在方案「细节参数 → 视觉投影文件」里选中它，重启引擎后就能看图。

注意：一张图会折算成上千 token，纯 CPU 处理一张图要几分钟，属正常现象。

## 常见问题

**模型加载很慢或卡住。** 看「运行状态」里的引擎日志。首次加载大模型要几十秒很正常；装不下时程序会自动降档重试（GPU 退 CPU → 上下文砍半），日志里能看到过程。

**速度很慢。** 小模型纯 CPU 本来就不快，跑分能帮你找到当前硬件最快的组合。想要快：换可用独显、更小的模型、或在细节参数里配投机解码草稿模型。

**第一句话要等很久。** 这是本地小机器跑 Claude Code 的主要瓶颈：每次请求带约 30K 提示词（系统提示 + 工具定义），纯 CPU 处理要几分钟。跑分报告会给你准确预估；续轮对话因为「长对话 KV 复用」只算新增内容，会快很多。

**它不会动手，只会一直说话。** 这是模型本身工具调用能力弱，不是配置问题。按能力档标注选「能扛工具调用」的模型（如 Qwen3-4B-Instruct、Qwen2.5-Coder-7B）。

**它看不见我发的图。** 多模态模型需要配置 mmproj 投影文件（见上节），没配就看不见图。普通文本模型配了图也看不见。

模型接好了，也可以继续看 [连接模型服务](../start/models.md) 里的云端模型接法。
